## T-5 진행 기록 (2026-11-25)

- 사용자 결정: 집중도만 먼저(기반 시스템). 집중도 = LLM이 그 NPC의 판단에 들이는 노력. 소 사건을 성격대로 얼마나 신경 쓰는지 LLM이 정한다(대충 넘기면 최하, 편집증이면 최고). 말은 집중도와 상관없이 노이즈 없이 들리고(거리 노이즈는 그대로), 이름이 불리는 등의 키워드가 없으면 노력이 낮다. 말풍선 겹침은 나중 아이디어.
- 구조: `Npc/NpcAttention`(값 0~1, 시트의 `baselineAttention`으로 반감기 60초 감쇠, 이름이 들리면 0.6 이상, 단계 낮음/보통/높음 → 기억 줄 수와 `LlmRequestOptions`). `Llm/LlmRequestOptions`(요청마다 생각 단계 `reasoning_effort`와 답 길이). NPC JSON 답에 `attention` 추가. 프롬프트에 지금 집중도와 고르는 법.
- 확인: Ollama에 직접 물어 qwen3:8b가 JSON 모드에서 생각을 켜도 대사와 생각이 따로 온다(생각 약 250~330토큰, 몇 초).
- 시뮬레이션 검증(플레이어 말은 코드로): "창고 식량 없다! 누가 가져갔다?" → 한도윤 0.5→0.8(높음, 생각 켬), 서미라 0.4→0.6, 박건우 0.2→0.3→0.2. 처음엔 높음의 답 길이 800에서 생각이 잘려 대사가 비었고(E-005 "..."), 2000으로 늘린 뒤 실패 0. 먼 곳에서 "박건우 너 어젯밤..." → 노이즈로 "박건○"가 되어 이름을 못 알아들음. 가까이서 부르자 박건우 0.2→0.6(이름)→0.7(LLM).
- 남은 것: 생각을 켜면 답이 몇 초 늦다. 높음 단계가 자주 나오면 대화가 느려질 수 있다.
- 다음(T-5 뒤): 추천 순서대로 T-3 또는 나머지 상태(NPC 이동 AI와 함께).

- 입력: 스페이스 = `Player/Talk` (Jump에서 스페이스를 뺐다). 대화창 안: 글자 → 후보, 스페이스/탭 고르기, ↑↓, 엔터 보내기(치던 글자가 있으면 먼저 고르기), Esc 닫기. 고른 단어는 고칠 수 없다(R-015a). 자동완성은 조합 중 글자("차"→창고)와 초성("ㅊㄱ")도 맞춘다.
- 캐릭터끼리 몸이 부딪히지 않게 `Character` 레이어(8번)를 만들고 서로 충돌을 껐다. 카메라 y를 3 → 2.2로 내려 화면 아래에 대화창 자리를 만들었다.
- 시뮬레이션 검증: 스페이스로 열림·이동 꺼짐(E-003), 자동완성, 문장 전송 → NPC 답과 말풍선, 생각 중 "..."(E-004), 닫힌 문 너머·12유닛 밖에서는 못 들음, 문 열면 들음, LLM 실패 시 "..."+오류(E-005). 비밀 질문에 "잠들었다", "모르지"로 둘러댐.
- R-016b (사용자 지시): NPC의 반응(돌아보기, 대답할지)은 코드가 강제하지 않고 LLM이 고른다. 같은 호출에서 JSON `{"look_at": 이름 또는 "", "say": 대사 또는 ""}`로 받는다(`response_format: json_object`). 확인: 질문에는 돌아보고 답함, "고마워"에는 돌아보지 않고 "안녕."만.
- 시뮬레이션 주의: 에디터 창에 포커스가 없으면 Input System이 키보드를 꺼서(`ResetAndDisableNonBackgroundDevices`) 흉내 낸 키 입력이 무시된다. 포커스 상관없는 검증은 `DialogueWindow`의 public 함수를 직접 부른다.
- 확인 못 한 것: 실제 키보드로 한글을 치는 IME 조합 동작(코드로 흉내 낼 수 없음). 층 사이(천장)는 소리를 막지 않는다 — 막을지 사용자에게 물어볼 것.
- 교훈: 파일을 쓰는 도중에 유니티가 빈 파일을 먼저 읽어 컴파일 목록에서 빠지는 일이 있었다. 재가져오기·강제 컴파일로도 안 풀려 에디터 재시작으로 해결.

## 작업하며 얻은 교훈

- **검증은 중간 상태까지 찍는다.** 도착 위치만 본 테스트가 계단 순간이동 버그를 놓쳤고, 사용자가 직접 플레이로 잡았다.
- **실제 입력 흉내:** `InputSystem.QueueStateEvent`로 마우스 이벤트를 넣고 다음 프레임이 처리하게 둔다. 같은 호출 안에서 `InputSystem.Update()`를 부르면 `WasPressedThisFrame`이 놓친다.
- **실패 이유는 화면에 보여야 한다.** 내려놓기가 NoSpace로 계속 실패했지만 콘솔에만 찍혀서 사용자는 "안 된다"고만 느꼈다. 이후 미리보기와 커서로 해결했다.
- 사용자의 직접 플레이 기록은 에디터 로그(`%LOCALAPPDATA%\Unity\Editor\Editor.log`)에서 `[Player]` 줄로 찾을 수 있다.
