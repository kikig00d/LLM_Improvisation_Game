클로드 코드 플러그인에 Superpowers 추가.

플러그인은 여러 개의 '스킬(Skill)'과 관련 설정을 하나로 묶어 배포하는 설치 패키지임.

/

1. 플러그인(Plugin)과 스킬(Skill)의 관계

• 스킬 (Skill): 에이전트에게 특정 작업(예: TDD, 브레인스토밍, 코드 리뷰)을 수행하는 방법을 알려주는 개별 지침서(마크다운 문서)입니다. superpowers 내부에는 약 14개의 핵심 스킬이 들어 있습니다.
• 플러그인 (Plugin): 이 여러 개의 스킬과 자동 실행 규칙(Hook 등)을 한 번에 설치하고 관리할 수 있도록 묶어놓은 배포 단위(패키지)입니다. 즉, superpowers 플러그인을 설치하면 그 안에 들어있는 모든 스킬이 한꺼번에 내 Claude Code에 추가되는 것입니다.

/

사용할 주요 플러그인으로는, 
최적화 특화의 unity-perf
유니티에서 지원하는 unity
AI 코딩 에이전트가 시니어 개발자처럼 일하도록 프로그래밍을 보조하는 superpowers

이 정도.

# 재미의 핵심
해당 게임 재미의 핵심은 챗봇과 같이 '상황'에 몰입한 ai들과의 대화와 심즈나 크킹과 같은 캐릭터들 간의 상호작용을 관람하는 것 자체에 있다.
그런 탓에 조난 상황이나 살인사건 같은 것은 어떻게 보면 매우 자극적인 조미료에 가깝다.
특히, 살인사건은 그 자체로 캐릭터를 줄여줘서 크킹처럼 게임이 장기화되었을 때 캐릭터가 너무 많아서 생기는 문제가 줄어든다는 이점이 있다.
조난 상황은 또한 캐릭터들을 한정된 공간에 가두기에 오브젝트를 최소화할 개연성이 만들어진다.

## 결론
대화 검증도 초반에 가능한 게 좋다. 
로컬 llm 모델 라마를 통해 애초에 게임 속 가상환경 내에서 상호작용 가능해야 목표로한 재미를 테스트할 수 있다.

# 첫 마일스톤 전에 필요한 답

- 문과 상자 조작 키 : 시야각이 범죄에 얼마나 중요한지를 고려하면 차라리, 오브젝트와의 상호작용은 왼쪽 클릭, 시야 줌은 오른쪽이 나을듯하다.
- 시야와 층 : 저택 자체는 전체가 다 보이게 하되 내부 오브젝트는 전장의 안개에 가려진 상황으로 하며 투시는 같은 '방'(복도에서 상자 쌓인 곳이 있다면 그 뒤는 안 보임) 내부라도 안 되게 한다.
- 오브젝트 정리 : '바닥'에 일정 크기 이상(상자라던가) 오브젝트를 놓으면 시야를 가리지만, '벽장'이나 '창고'에 넣으면 캐릭터 이동과 시야에 방해가 되지 않는다.
- 상태바 종류 : 돈스타브나 더 롱 다크 같은 식으로, 바로 생각나는 건 '스트레스', '체온', '건강', '배고픔', '스테미너(피로)' 정도. 여기서, 건강은 상위이고 배고픔, 스테미너, 체온, 스트레스는 하위이며 하위 상태바가 일정 수치면은 패널티성 질병이나 역으로 보너스를 받을 수 있다. 
- 시간 속도 :  대충, 마인크래프트 하루 정도면 될 것 같음.
- 상자 : '장애'나 '질병' 같은 경우가 아니면 들 수 있되, 캐릭터 능력치에 따라 '스테미너' 소모량이나 이동속도가 변할듯.
- 배경 이름 : 카마이타치의 밤이 주된 모티브이니 산장이 맞을듯.
- 게임 이름 : 일단, '즉흥극'으로 생각 중. 관계의 랜덤 생성, 사건의 발생에 대한 난수적 이유.
- 잠자기와 NPC : 플레이어가 잠들어도 npc들은 깨어있는 한 상호작용을 계속한다. 대신, 게임 시간이 컴퓨터가 허락하는 한 가속한다.
- 만들지 않는 것 : 모바일은 현재 생각 없고, 음성은 현 ai 음성을 보면 생각해볼만한 문제일듯?

라마 사용법에 대해서 :
세 선택지의 차이

1. Ollama 서버

백그라운드에서 도는 작은 프로그램이에요. 내 PC 안에 "미니 구글 서버"를 띄운다고 보면 됩니다.
모델은 ollama pull 모델이름 한 줄로 받고, 바꾸는 것도 이름만 바꾸면 돼요.
step7과 같은 OpenAI 호환 주소를 줘서, Gemini를 부르던 방식을 거의 그대로 C#으로 옮기면 됩니다.
화면 없이 명령어로 쓰는 도구예요.

2. LM Studio 서버

Ollama와 하는 일은 같은데, 화면이 있는 프로그램이에요. 모델을 검색해서 받고, 채팅창에서 바로 시험해 보고, 버튼으로 서버를 켭니다.
유니티 쪽 코드는 Ollama와 똑같아요. 둘 다 같은 형식의 주소를 주거든요.
모델을 눈으로 비교하며 고르기는 편하지만, 매번 프로그램을 켜서 서버를 시작해야 해요.

3. 유니티 내장

별도 프로그램 없이 모델을 게임 안에 직접 넣어요. 유니티용 플러그인이 C++ 엔진을 품고 있는 방식입니다.
플레이어가 게임만 설치하면 되니 나중에 배포할 때 가장 편해요.
대신 모델이 게임 프로세스 안에서 돌아서, 문제가 생기면 게임과 같이 멈춥니다. 원인이 모델인지 내 코드인지 가리기 어렵고, 모델을 바꿀 때마다 유니티를 다시 불러와야 해요.
